# Grok Build native marketplace route

`grok` means xAI Grok Build, not Grok Bot. The active adapter uses Grok's native local marketplace, plugin install/update/enable/remove commands and installed-plugin registry. It materializes one plgnz-owned marketplace per selected logical plugin identity (`name@source-marketplace`), with a private ownership marker. It never adds a second standalone skill copy. A foreign same-name native install or marketplace root is refused unless the caller explicitly requests guarded adoption of one exact direct-local legacy install.

## Native contract and projection

The adapter also maintains `~/.grok/plugins/<name>` as a guarded symlink to the registered native installed copy. This is activation, not a second content copy. Grok automatically imports Claude plugins; without the native user-directory entry, a same-name Claude plugin can shadow a marketplace install. [Official discovery order](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/09-plugins.md) documents native user plugins. The adapter refuses foreign directories or links, repairs missing activation on re-add, cleans new links after failed activation, and removes its matching link on uninstall. Claude files and compatibility settings remain untouched.

It failed before this fix and passes on Grok 1.0.24 and 1.0.41. The full local suite retains the same ten unrelated failures as baseline `092edd1`; these are not claimed green. No skill instructions were changed.

The inspected Grok source checkout has `SOURCE_REV` `a549186d9d39311f2d3ee4208db62af8c65aa476`; the exercised isolated npm binary is `@xai-official/grok@1.0.41`, reporting `grok 1.0.41 (4220f3b224a6)`. The source and binary revisions differ, so source explains the mechanism while the 1.0.41 CLI/loader probe establishes this binary's behavior. Grok resolves its store from `GROK_HOME` (`xai-dirs/src/lib.rs`). The adapter sets it to `OPEN_PLUGIN_GROK_ROOT` and sets `HOME`/XDG paths for an isolated invocation.

Grok's marketplace scanner accepts `.grok-plugin/marketplace.json` with a local `./plugins/<name>` entry (`xai-grok-plugin-marketplace/src/index.rs`, `scanner.rs`). The adapter copies the selected source plugin, writes that index, validates the staged plugin, then uses `grok plugin install <name>@local/<marketplace> --trust` or `grok plugin update <name>`. The native marketplace updater stages and swaps the installed copy transactionally (`installer.rs`, `update_from_marketplace_entry_transactional`). plgnz checks the activated native tree and empty-cwd `grok inspect --json` before recording success. Its marker carries both the original source fingerprint and the projected native fingerprint; the source bytes, including Personal vendor amendments and provenance, remain authoritative.

Session start scans marketplaces and fans out plugin updates unless `plugin_auto_update = false` is set. The pinned user guide names that key, and `pluginAutoUpdate = false`, as a global tighten-only pin with no per-marketplace equivalent and no Claude counterpart. Manual `grok plugin update` still works. The key is a top-level entry in a grok TOML policy layer (`managed_config.toml`, `requirements.toml`, or a self-imposed user-writable `~/.grok` copy), ahead of any `[table]`. [Turn off session-start plugin auto-update](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-pager/docs/user-guide/09-plugins.md#turn-off-session-start-plugin-auto-update). The lifecycle adapter writes `plugin_auto_update = false` at the top of `config.toml` and snapshots the previous file text. Rollback restores that text, and an aborted preparation restores it before deleting the record.

Native `skills/*/SKILL.md` and `commands/*.md` are discovered under the installed plugin. Grok parses `disable-model-invocation`, `user-invocable`, `argument-hint`, `$ARGUMENTS`, and positional `$1`/`$ARGUMENTS[N]` (`xai-grok-tools/src/implementations/skills/discovery.rs`, `skill.rs`). plgnz preserves ordinary skill discovery, translates a Codex `agents/openai.yaml` implicit-invocation policy into Grok frontmatter when needed, normalizes supported alias spellings, and rejects contradictory policies. Prompt-only TOML commands become native Markdown commands with the original prompt body and argument tokens; executable preprocessing and unverified permission semantics are refused. `.mcp.json` and manifest MCP declarations stay inside the native plugin, and a lone spec `mcp.json` is copied to Grok's `.mcp.json` path. The reader exposes plugin MCP entries to doctor; the writer applies requested MCP command pins without entering doctor's import graph.
